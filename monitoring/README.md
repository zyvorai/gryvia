# Gryvia monitoring assets

Alert rules and Grafana dashboards that reference only metrics Gryvia (or a documented third-party exporter) really exports.
Everything, including the metric catalog, how to enable it and its limits, is documented in
[docs/observability.md](../docs/observability.md).

| Path | What |
|---|---|
| `prometheus-rules.yaml` | 18 alerts, plain Prometheus rule-file format (`promtool check rules` works on it) |
| `grafana-dashboards/*.json` | 13 raw Grafana dashboards, generated by `scripts/gen-dashboards.py` (edit the generator, not the JSON) |
| `external-metrics.txt` | Allow-list of non-Gryvia metrics the assets may use (dcgm-exporter, kube-state-metrics, controller-runtime, ...) |
| `../docs/runbooks/` | One runbook per alert; each alert's `runbook_url` points at it |

Checks that run in CI (`.github/workflows/repo-checks.yml`), all runnable locally:

```bash
python3 scripts/gen-dashboards.py && git diff --exit-code monitoring/   # dashboards match the generator
python3 scripts/check-metrics-refs.py                                   # every metric name is exported or allow-listed
python3 scripts/check-monitoring-assets.py                              # structure of rules and dashboards, runbooks exist
scripts/sync-monitoring-assets.sh --check                               # Helm chart copies are current
```

After changing anything here run `scripts/sync-monitoring-assets.sh` and commit the copies under `helm/*/monitoring-assets/`.

The previous `servicemonitor.yaml` was removed: its selectors matched labels no chart sets. The Helm charts create the monitors now.
